# D435i + iQOO Z7x：深度与有声视频录制

日期：2026-10-14。需求：Android 13 手机控制 D435i，手机自带麦克风录音，同时保留深度数据和有声 MP4。

## 安装与使用

开发版名为 **RS Camera AV**，包名 `com.intel.realsense.camera.av`，版本 `0.0.8-rgb-audio` / 8。它与原 RS Camera 共存；原应用的设置和录制文件不会自动迁移到新应用。

安装包：`outputs/RS-Camera-0.0.8-rgb-audio-arm64.apk`。原来的 `apk/RS-Camera-0.0.7-rgb-arm64.apk` 保留原样。

1. 把新 APK 传到手机安装，打开 **RS Camera AV**，允许相机权限。
2. 开启手机 OTG（如果系统提供开关），用支持数据的 OTG 线连接 D435i，允许 USB 访问。
3. 先确认实时 RGB 画面。设置中同时开启 **COLOR** 和 **DEPTH**。录制会沿用所选采集分辨率、帧率及其他流，不会暗中更改流配置。
4. 首次点击录制时允许麦克风权限。手机麦克风隐私开关需要开启；电话或其他录音应用占用麦克风时可能无法正常录制。
5. 首次先录 30 秒：对着相机拍手并说话，点击停止，等“录制已保存”提示。
6. 点击“播放 / 导出 MP4”听声音、看画面；“导出文件”可单独导出 MP4、BAG、同步信息，或将全部文件打包为 ZIP。原“Playback”入口也可重新选择 BAG 或 MP4。

这一版只在录制页面处于前台时采集。返回、切到其他应用或锁屏，会停止并尝试保存；恢复页面不会自动开始下一段。旋转屏幕不重启采集。强制结束进程、断电等情况无法保证 MP4 能完成封装。

官方参数说明 Z7x 支持 OTG。USB Type-C 接头本身不代表 USB 3 带宽；能用的组合以应用实际显示的流列表和真机结果为准。先使用较低分辨率/帧率验证，稳定后再提高；若设置中提供，可以先试 COLOR RGB8 640×480、DEPTH Z16 640×480、15fps。供电不足或线材不可靠时，可使用支持手机作为 USB Host 的外供电 Hub。

## 一次录制的文件

所有文件同名，例如：

```text
20261014_120000_123.bag         原始颜色、深度及设置中启用的其他 RealSense 流
20261014_120000_123.mp4         彩色视频 H.264 + 手机麦克风 AAC，48kHz 单声道
20261014_120000_123.sync.json   配置、时钟基准、保存状态、错误信息
20261014_120000_123.frames.csv  已送往 MP4 的颜色帧与对应深度帧的时间映射
```

**BAG 内不嵌入手机声音。** 音频保存在同名 MP4 的音轨中。需要结合深度和声音分析时，应保留同名的全部文件。

录制中的 MP4 使用 `.mp4.part`；正常完成编码和封装后改名为 `.mp4`。失败时保留 `.part` 和错误信息，文件列表不会把它当成已保存录像。停止时会尽量保存 BAG，但发生硬件断开、空间耗尽或进程被杀时仍应检查文件是否能回放。

应用内路径：`getExternalFilesDir(null)/realsense/video/`。

Android 13 上通常对应：

```text
/sdcard/Android/data/com.intel.realsense.camera.av/files/realsense/video/
```

可使用应用的“导出文件”按钮，或电脑 ADB：

```powershell
adb pull /sdcard/Android/data/com.intel.realsense.camera.av/files/realsense/video ./recordings-av
```

卸载新开发版也会清除新开发版的应用文件，应先导出所需文件。

## 同步的含义

视频采用颜色帧到达手机采集线程时的 `System.nanoTime()`；音频优先采用 `AudioRecord` 的 MONOTONIC 采样时间戳。二者统一到 MP4 录制的单调时钟起点，以微秒写入编码器。音频设备暂时未提供时间戳时，使用首批采样的读取时间及采样数量估算。

这是软件时间同步。USB 传输、帧等待、手机音频驱动会引入延迟，**尚未测量实际音画误差，也不承诺硬件级同步或毫秒级精度**。真机应测试开头与结尾的拍手动作，检查长时间录制是否漂移。

BAG 从 Pipeline 开始运行时就录制，MP4 在取得颜色/深度帧并初始化编码器后开始，因此 BAG 可能包含 MP4 开始前的一段帧。CSV 只映射送往 MP4 的帧，不是全部 BAG 帧清单；不能单凭文件名或首帧就认为两个文件的起点完全一致。同步 JSON 记录 MP4 时钟基准，CSV 记录颜色/深度帧编号、设备时间戳和时间戳域、手机到达时间、MP4 输入 PTS。帧丢失或 USB 延迟仍可能影响映射精度。

## 主要修改

相对于 `source/librealsense-2.58.1/wrappers/android`：

| 文件 | 作用 |
|---|---|
| `tools/camera/.../RecordingActivity.java` | 正确等待相机/麦克风授权、开始/停止录制、状态提示、保存结果 |
| `tools/camera/.../RecordingSession.java` | 独立 HandlerThread 上的 RealSense 采集、BAG/MP4 配对、同步信息与存储检查 |
| `tools/camera/.../AvRecorder.java` | AVC/AAC 编码、手机内置麦克风选择、音视频时间戳、双轨 MP4、停止时排空编码器 |
| `tools/camera/.../EncoderSurface.java` | 独立 EGL 上下文，将 RGB/RGBA 画面送入硬件视频编码器 |
| `tools/camera/.../RgbPreviewSurfaceView.java` | 从包内交接补丁恢复缺失的 RGB 预览类，最多保留一个待显示帧 |
| `tools/camera/.../Streamer.java` | 帧循环错误通知和停止时的资源释放 |
| `tools/camera/.../VideoPlaybackActivity.java` | 带声音 MP4 回放、分享、单文件/ZIP 导出 |
| `tools/camera/.../PlaybackActivity.java`、`FileBrowserActivity.java` | 回放入口区分 BAG 与 MP4，过滤同步文件和未完成文件 |
| `tools/camera/src/main/AndroidManifest.xml` | 录音权限、回放页面、限定到录制目录的 FileProvider |
| 横/竖屏录制布局 | 录制时长及保存状态 |
| `tools/camera/build.gradle`、应用名称、构建/安装脚本 | 版本 8、开发版共存及新 APK 名称 |

声音采集使用独立线程，muxer 访问串行化。等待音视频轨道时最多缓存 8MiB；录制页面不执行阻塞采集和编码。COLOR 当前支持 RGB8、RGBA8 和 YUYV；YUYV 经 SDK 解码后再编码。空间不足、麦克风被系统静音/切换、采集报错时停止，并提示保存结果。

## 构建

Android Studio 打开 `source/librealsense-2.58.1/wrappers/android`，运行 `tools.camera`。完整原生构建使用原脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1 -SdkPath "C:\Android\Sdk" -JavaHome "C:\Java\jdk-17"
```

完整构建仍需要 NDK/CMake，并建议使用短英文目录。只修改 Java/界面时，新增一个不需要 NDK/CMake 的构建入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-java.ps1 -SdkPath "C:\Android\Sdk" -JavaHome "C:\Java\jdk-17"
```

它在 `.work` 中创建独立构建目录，重新编译当前 Java 和 Android 资源，提取原 0.0.7 APK 中的 `librealsense2.so`，并输出应用 APK 和真机测试 APK。**修改 C++ 或 JNI 时必须用完整原生构建，不能沿用旧 native 库。** 未修改源码工程的 native 构建配置。

安装新 APK（ADB 已授权，手机 ARM64）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -SdkPath "C:\Android\Sdk" -ApkPath ".\outputs\RS-Camera-0.0.8-rgb-audio-arm64.apk" -ApplicationId "com.intel.realsense.camera.av"
```

## 验证范围

这次已执行的编译/签名检查见 `docs/音视频构建验证.txt`。没有连接 D435i 和 iQOO Z7x 实测，因此采集带宽、供电、麦克风路由、编码器兼容性和音画误差仍待设备验证。

增加了 `AvRecorderInstrumentedTest`：在 Android 设备上录制三秒红/蓝测试图及实际麦克风，检查两条音视频轨道、递增时间戳、至少两秒重叠，以及画面没有上下颠倒。测试会使用手机麦克风，需要用户知情地运行；本次没有执行此真机测试。编译测试包不等于测试通过。

连接设备后可运行：

```powershell
adb install -r .\outputs\RS-Camera-0.0.8-rgb-audio-arm64.apk
adb install -r .\outputs\RS-Camera-AV-androidTest.apk
adb shell am instrument -w com.intel.realsense.camera.av.test/androidx.test.runner.AndroidJUnitRunner
```

手工测试还需要覆盖：拒绝麦克风权限、30秒拍手与说话、连续录制10分钟、横竖屏切换、反复开始/停止、切到后台/锁屏、拔插相机、系统麦克风隐私开关、低存储情况、导出ZIP后在电脑用 RealSense Viewer 打开 BAG。测试时确认 MP4 画面来自 D435i，而不是手机相机。

原来的 `SHA256SUMS.txt` 和旧交接文档对应 0.0.7 包；新功能请以本说明、新验证记录和 `SHA256SUMS-audio-video.txt` 为准。
