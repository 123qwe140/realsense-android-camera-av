当前数据流程

Streamer 按 SettingsActivity 保存的流配置启动 Pipeline。
每个 FrameSet 保留原始的颜色和深度数据；录制通过 Config.enableRecordToFile 写传统 .bag。
PreviewActivity 与 RecordingActivity 使用 RgbPreviewSurfaceView，只从 FrameSet 提取 COLOR 帧送往显示。
RGB8/RGBA8 走原渲染器的单帧上传；YUYV 按需使用 YuyDecoder。
显示不对深度进行着色，也不计算点云；GLSurfaceView 使用 RENDERMODE_WHEN_DIRTY。
最多保留一个等待显示的颜色帧，使用 clone/close 保持原生帧引用生命周期；在 GL 线程上传和清理资源。
录制发生在 Pipeline 内，不取决于预览是否丢弃一个等待显示的颜色帧。
没有降低采集分辨率或采集帧率。采集流是否包含深度，仍由设置决定。
PlaybackActivity 保留官方回放界面，包括多流与 3D 回放；目前 RGB 改造仅覆盖实时预览与录制界面。

录制文件位置

Android 应用的 getExternalFilesDir(null)/realsense/video/*.bag。
原包名的常见对应路径为 /sdcard/Android/data/com.intel.realsense.camera/files/realsense/video/。
部分系统的文件管理器限制访问 Android/data，可通过电脑 ADB 导出：
  adb -s 目标设备序列号 pull /sdcard/Android/data/com.intel.realsense.camera/files/realsense/video ./recordings
更改包名后路径中的包名也要更改。
为验证“仍录深度”，可将文件导出到电脑，用 RealSense Viewer 查看录制流。

继续优化的重点

先在 iQOO 真机验证 RGB8 与 YUYV、横竖屏、暂停恢复与多次录制后的内存占用。
当前 Streamer.waitForFrames 和回调使用主线程 Handler；若出现 UI 卡顿，可考虑独立采集线程，注意 UI 更新与停止/关闭之间的同步。
GLVideoFrame 仍会复制 RGB 像素并上传纹理；可以进一步减少像素复制与重复纹理分配，但应先取得真机性能数据。
RGB 预览依赖 COLOR 流：如果只开启 DEPTH，将没有 RGB 画面。
首次请求或拒绝相机/USB 权限、相机掉线和低供电状态都应在接手设备上验证。
Android SDK 的官方工具不覆盖本项目所有手机系统行为；不要将三星实测等同于 iQOO 已适配。
